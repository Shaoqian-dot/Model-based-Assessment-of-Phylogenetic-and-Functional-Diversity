Data Generation

## Abundance matrix
abundance <- mu_eta_site
abundance[] <- rbinom(length(mu_eta_site), size = 1, prob = mu_eta_site)

# Create community factor (1:q repeated r times each)
com <- factor(rep(1:q, each=r))

# Combine abundance matrix and community labels into a data frame
yX <- data.frame(abundance, com)

## Long format abundance data
yX <- reshape(yX, direction = "long", varying = colnames(abundance),
              v.names = "y", timevar = "sp")

# Convert species column to factor
yX$sp <- factor(yX$sp)

Modelling

model <- glmmTMB (y ~ com * sp + rr(sp + 0 | id, 2),
                  family = 'binomial',
                  data = yX)

Prediction

## Extract fixed effects 
eta_T_fe_hat <- predict(model, 
                   type = "link",
                   re.form = NA)

# Arrange the fixed effecs into a matrix
eta_T_fe_hat_M <- matrix(
  as.numeric(eta_T_fe_hat),
  ncol = p,
  byrow = FALSE
)

# Calculate row centered fixed effects 
eta_R_fe_hat <-  eta_T_fe_hat - apply(eta_T_fe_hat_M, 1, mean) 

##  Extract random effects
RR <- simulate_random_effects(model = model)

## Calculate eta_B and mu_eta_B
eta_R_hat <- eta_R_fe_hat + RR
mu_eta_R_hat <- expit(eta_R_hat)

The function Biplot() projects \(\eta_B\)/\(\mu_B\) along the first two eigenvectors of \(S\) and \(S_J\). Changing \(S\) to \(S_J\) is to determine if we want to exclude vector \(\boldsymbol{1}\) in the projection space. The biplot shows that the way that the 6 communities are arranged in biplot is different when using \(S\) and \(S_J\). Specifically, for the case using \(S\), where the projection space does not exclude vector\(\boldsymbol{1}\), the plots shows that the correlation is almost parallel to \(v_1\), and com 4 moves downwards directly along \(v_2\) obviously, and com 6 hardly moves away from com 1; In terms of using \(S_J\), namely the projection space excludes vector 1, com 4 (diversity decreases) and com 6 (diversity increases) moves towards different directions along the anti-diagonal, which may imply that diversity decreases towards unpper-left anti-diagonal and increases towards down-right anti-diagonal. Hence, the comparison of using \(S\) or \(S_J\) illustrates that projecting \(eta_B\)/\(mu_B\) into the space excluding vector \(1\) is more reasonable. In fact, including vector \(\boldsymbol{1}\) is useless because there is no diversity change along \(\boldsymbol{1}\) when we are studying relative diversity.

In terms of the comparison of projecting \(\eta_B\) or projecting \(\mu_B\), the plot show that there is no obvious difference either we project \(\eta_B\) or \(\mu_B\) except for the axes scale.

Concerns

1 A concern for the current design when \(\#\) species is uneven numbers is the values of relative abundance at the logit scale and abundance scale are not convertible into each other. For example, for com 1, relative abundance at mean abundance scale is \((0.8, 0.2, 0.8, 0.2, 0.8)\); However, relative abundance at logit scale, if we have a sum-to-zero constraint on relative abundance on logit scale, is \((1.39, -1.39, 1.39, -1.39, 1.39) - 0.28 = (1.11, -1.63, 1.11, -1.63, 1.11)\) (0.28 is the vector average of \((1.39, -1.39, 1.39, -1.39, 1.39)\)). Then, the transformed relative abundance from logit scale to abundance scale by \(g^{-1}\) is \((0.75, 0.16, 0.75, 0.16, 0.75)\), which is not equal to \((0.8, 0.2, 0.8, 0.2, 0.8)\). My question is that if \(\mu_B = g^{-1}(\eta_B)\) reflect the true relative abundance. The concern disappears when \(\#\) sp is enven number because relative abundance we design at logit scale satisfies a sum-to-zero constrtaint.

Conclusions

1 When we are studying relative abundance, \(\mu_B^{\top} D \mu_B\) can reflect the true diversity . However, we need to think about if \(\mu_B\) represents relative abundance when the number of species in uneven.

2 For projecting \(\eta_B\) or \(\mu_B\), the projection space should exclude vector \(\boldsymbol{1}\).

3 For determining projecting \(\eta_B\) or \(\mu_B\), there is no big difference either projecting \(\eta_B\) or \(\mu_B\).
